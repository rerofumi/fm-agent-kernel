# 5. ドライバ層・観測性・主要 OS アーキテクチャカタログ

外部連携の抽象化、実行時観測（Observability）、および歴史的・現代的な代表的 OS の特徴を網羅的にまとめる。

---

## 5.1 デバイスドライバ・HAL・プラグイン安全性

### HAL (Hardware Abstraction Layer)
- Windows NT や Android などで採用。ハードウェア（チップセット・バス・割込コントローラ等）の差異を吸収し、上位カーネルやサービスを移植可能にする薄い層。

### カーネル空間ドライバ vs ユーザー空間ドライバ
- **カーネル空間ドライバ**: 高速だが、バグやハングがシステム全体を巻き込む（Linux/Windows の BSOD や Kernel Panic の主要因）。
- **ユーザー空間ドライバ**:
  - マイクロカーネル（QNX, MINIX 3, Zircon, Genode）では基本構造。Linux でも UIO / VFIO / FUSE / CUSE / libusb で利用される。
  - **保護**: ドライバがクラッシュしてもプロセス単位で再起動でき、カーネルや他アプリを道連れにしない。
- **Nooks（研究プロジェクト）**: 既存モノリシックカーネルのドライバを軽量な保護ドメイン（Shadow Driver）で囲み、クラッシュ時に回復させる試み。

### 標準化された仮想デバイスプロトコル（Virtio 等）
- 多数のゲスト OS × 多数のハイパーバイザ間で「N×M のドライバ爆発」を防ぐため、共通のキュー・リングバッファベースの標準インターフェース（**Virtio**: virtio-net, virtio-blk, virtio-fs 等）を定義する。
- プラグインや外部連携（LLM プロバイダ、MCP、Git 等）を「ドライバ」として扱う際のインターフェース標準化（1対多の正規化）の好例。

### プラグイン / 拡張の安全設計
- **ABI 安定性 vs ソース互換**: Linux カーネルは内部 ABI を固定せず変更を許容する一方、Windows (WDM/WDF) や macOS (DriverKit) はドライバ開発キットで明示的な契約・フレームワーク境界を設ける。
- **Wasm / eBPF 型サンドボックス**: 非信頼のサードパーティプラグインをプロセス隔離または検証付き VM（WASI / eBPF）で動かし、明示的に渡したホスト関数（System Call）以外は呼べないようにする。

## 5.2 観測性（Observability）・監査・リプレイ

### システムコールトレーシング
- **`strace` (Linux) / `truss` (Solaris/FreeBSD) / `ktrace` (BSD)**:
  - `ptrace` 等を用いてプロセスがカーネルへ発行するすべてのシステムコール（引数、戻り値、エラー、所要時間）を記録する。
  - プログラムが「実際に環境に対して何をしたか」をソースコードなしで把握できる究極のブラックボックス検査。
  - 注意点: `ptrace` ベースはコンテキストスイッチが多発しオーバーヘッドが大きい。

### 動的トレーシング・インストルメンテーション
- **DTrace (Solaris / FreeBSD / macOS)**:
  - 本番環境でも安全に動かせる動的トレース基盤。プローブポイントに安全なバイトコード（D 言語）を仕込み、オーバーヘッドがゼロ（未使用時）〜極小でカーネルとユーザー空間を横断計測。
- **eBPF / `bpftrace` (Linux)**:
  - DTrace の思想をさらに拡張。検証器により安全性を担保しつつ、あらゆるカーネル関数・トレースポイント・uprobe でイベント集計・フィルタ・リアルタイム監視を行う。
- **ETW (Event Tracing for Windows)**: 高速・構造化・低オーバーヘッドなカーネル／アプリ横断イベントログ基盤。

### 監査サブシステム（Audit）
- **Linux Audit (`auditd`) / OpenBSM**:
  - デバッグ目的のトレースとは異なり、**改ざん耐性・網羅性・コンプライアンス** を重視。「誰が・いつ・どの権限で・どのファイル/リソースに・どのシステムコールを発行し・成功/失敗したか」を構造化ログとして強制記録する。

### 決定論的リプレイ（Time-Travel Debugging）
- **`rr` (Mozilla) / UndoDB / Simics**:
  - プログラム実行中の非決定論的入力（システムコールの戻り値、シグナル、時刻、乱数）をすべて記録しておくことで、後から **1命令単位で巻き戻し（Reverse Execution）・完全再現** できる。
  - 非決定論的な振る舞いをする主体（並列プログラムや外部応答を含むエージェント）のデバッグにおいて極めて重要な発想。

## 5.3 主要 OS アーキテクチャカタログ（時代別・思想別）

### A. 歴史的基盤・影響源
| OS | 時代/出典 | 核心アーキテクチャと後世への遺産 |
| :--- | :--- | :--- |
| **Multics** | 1960s (MIT/GE/Bell) | 単一レベルストア（メモリとファイルの統一）、8段階保護リング、動的リンク、階層セキュリティ。UNIX や現代仮想記憶の母体 |
| **UNIX (V6/V7)** | 1970s (Bell Labs) | 単純さ（KISS）、すべてはファイル、パイプとフィルタ合成、`fork`/`exec`、ポータブルな C 実装 |
| **KeyKOS / EROS** | 1980s-90s | 純粋ケーパビリティ OS、単一レベルストア＋定期チェックポイントによるシステム全体の永続化・無停止再開 |
| **Mach** | 1980s-90s (CMU) | ポートとメッセージによる IPC、外部ページャ（External Pager）、Task/Thread 分離。macOS XNU や Hurd に継承 |
| **Plan 9** | 1980s-90s (Bell Labs) | 9P プロトコル、プロセスごとのプライベート名前空間、テキストインターフェース、分散リソースの透過的マウント |
| **Inferno** | 1990s (Bell Labs) | Plan 9 の思想を仮想マシン（Dis VM）と Limbo 言語上に載せたポータブル分散 OS。ホスト OS 上でも動く |
| **BeOS / Haiku** | 1990s / 現在 | パーベイシブ・マルチスレッディング、データベースライクなファイルシステム（BFS: 属性インデックス検索）、クリーンな C++ API |

### B. 汎用・商用主力 OS
| OS | 分類 | 特筆すべきアーキテクチャ要素 |
| :--- | :--- | :--- |
| **Linux** | モノリシック (LKM) | Namespaces, cgroups v2, VFS, OverlayFS, `io_uring`, eBPF, `seccomp-bpf`, Landlock。現代コンテナ・クラウド基盤の事実上の標準 |
| **FreeBSD** | モノリシック | Jails, ZFS 統合, DTrace, `kqueue`, **Capsicum**（既存アプリを能力ベースにサンドボックス化） |
| **OpenBSD** | モノリシック | 攻撃面削減・プロアクティブセキュリティ、`pledge`（自己制限システムコール）, `unveil`（FS 視界制限） |
| **Windows NT** | ハイブリッド | オブジェクトマネージャ中心設計（全資源をオブジェクト＋ハンドル＋ACL で統一管理）、HAL、IRP（I/O Request Packet: 非同期 I/O パイプライン）、ALPC、ETW |
| **macOS (XNU)** | ハイブリッド | Mach マイクロカーネル（IPC/VM/スケジューリング）＋ BSD 層（POSIX/VFS/ネット）＋ I/O Kit（C++ ドライバフレームワーク）＋ APFS (CoW) |

### C. 高信頼・組込み・マイクロカーネル系
| OS | 分類 | 特筆すべきアーキテクチャ要素 |
| :--- | :--- | :--- |
| **QNX Neutrino** | マイクロカーネル | 同期メッセージパッシング（`MsgSend`/`Receive`/`Reply`）とパルス、リソースマネージャ（ファイルシステム風インターフェースをユーザープロセスが容易に実装） |
| **MINIX 3** | マイクロカーネル | 自己修復（Reincarnation Server）、ドライバ権限の極小化、POSIX 互換ユーザー空間サーバー群 |
| **seL4** | マイクロカーネル | 形式検証済みカーネル、ケーパビリティ空間（CSpace）、カーネル内動的割り当て排除（Untyped Memory）、最高水準の隔離保証 |
| **Genode / Sculpt** | フレームワーク / OS | 再帰的プロセスツリー、親による完全な環境定義、セッション単位の資源寄贈（Quota Donation）、複数マイクロカーネル上で動作 |
| **Fuchsia / Zircon** | マイクロカーネル | オブジェクトケーパビリティ（Handle + Rights）、Zero Ambient Authority、Channel + FIDL、Component Framework（宣言的コンポーネント合成） |
| **Hubris (Oxide)** | 組込みマイクロ | 約 2,000 行の Rust カーネル、動的確保なし（全タスク静的定義）、同期ランデブー IPC（キューなし）、Supervisor タスクによる復旧、Idol (IDL) |

### D. 新世代言語 OS・仮想化・宣言的 OS
| OS | 分類 | 特筆すべきアーキテクチャ要素 |
| :--- | :--- | :--- |
| **Singularity / Midori** | 言語ベース OS | SIP（Software Isolated Processes）、契約チャネル＋所有権移転（Zero-copy）、マニフェスト静的検証 |
| **Redox OS** | マイクロカーネル (Rust) | Rust 製マイクロカーネル＋完全マイクロカーネル構成、Plan 9 に着想を得た **URL スキームベースのリソース指定**（`file:`, `display:`, `network:`） |
| **Theseus OS** | Intralingual OS (Rust) | 単一アドレス空間、**State Spill の排除**、Cell モジュール単位のライブ置換・個別復旧、コンパイラへの簿記委譲 |
| **Asterinas** | Framekernel (Rust) | モノリシック並みの性能とマイクロカーネル並みの最小 TCB の両立。OSTD（`unsafe` 隔離層）と Safe Rust サービス層の明確な境界 |
| **MirageOS / Unikraft** | ユニカーネル | コンポーネント合成型の Library OS。最小イメージ、ミリ秒起動、極小攻撃面 |
| **Qubes OS** | コンパートメント OS | Xen ハイパーバイザ上で用途別に VM 分離。信頼できない操作を Disposable VM（使い捨て VM）で実行し即破棄 |
| **NixOS / Guix** | 宣言的 / 関数型 OS | 不変ストア＋依存ハッシュ管理＋原子的世代切替・ロールバック |
