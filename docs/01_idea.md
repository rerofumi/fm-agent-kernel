# 自作コーディングエージェント作成調査プロジェクト

## つくるもの

自作のコーディングエージェントエンジン

## 目的

- 自作コーディングエージェントは作れるか、作ったとしてどれくらいのものになるのか
- 実際にざっくりと作って調べようというプロトタイピングプロジェクト
- なぜコーディングエージェントを自作したいか
  - bot、AIチーム、カンバンタスク といった要素に最大限の期待をしている
  - 今これらを満足な形で備えているアプリが無い
  - 自分で欲しいものを作ってみるか
  - bot、AIチーム、カンバンタスク、が目指すところだけれどもまずは実際に使えるコーディングエージェント、ファイル操作ができるエージェントをターゲットとする

## 欲しい機能

- モジュラーシステム
  - プロバイダ、ツールコール、フック、スキル、といった要素をプラグイン化、本体は最低限の実装とする
- 人間のプロンプト入力ごとにプロバイダとモデルを切り替えられる仕組み、なるべく切り替えが容易になる様 UX を組む
- API 入出力の監視、ロギング(主にデバッグ用)
  - 最近はトークン量だけでなく、キャッシュヒットも大きな要因になってきたのでキャッシュも監視したい
- ACP による上位 UI 部分の切り離し
  - 今回作るのは ACP Interface から下の部分、本当に原理試作だけできるように切り分ける
  - テスト用の簡易 ACP クライアントも必要ではある

## 技術アイディア

- Dart で作りたい
  - 型厳格でフォーマッターが存在する言語、エージェントで組んでもルールがあるのでフォーマットが崩れにくい
  - Windows NATIVE DLL が使え、exe にビルドできる
- 既存の OS を参考にする
  - カーネルはエージェントループではなく、システムコールの層にする。
  - ユーザーがシステムコールで依頼すると、マイクロエージェントカーネル（プロセス）が起動し、エージェントループを回す。
  - カーネル部分が危険な操作を抑止する防波堤になる。
  - 資源が必要になったら、システムコール（tool call）でカーネルに要求する。リングのレベルによっては、その間にユーザーの許可確認が入る。
  - プロセスは新しいプロセスを生成でき、メールボックスでほかのプロセスとメッセージをやり取りする（Actor モデルに近い）。
  - 狙いは、メンテナンスと拡張がしやすい、見通しのよいシステムにすること。

発展案:

1. ケイパビリティ方式にする。子には親の権限の一部だけを渡す。
2. 資源の上限（rlimit や cgroup に相当）を設ける。対象はトークン、費用、時間、子の数。
3. シグナルと supervisor でプロセスを監督する。
4. 仮想ファイルシステムと名前空間を使い、書き込みは Copy-on-Write でためて、トランザクションとロールバックを実現する。
5. 全システムコールを監査ログ（strace に相当）に残す。
6. 文脈管理をページングとみなす。
7. 外部連携（LLM の提供元、MCP、git）をドライバ層として扱う。
