## 4. 非機能要求・制約・互換性および検証範囲

### 4.1 適用される非機能要求・アーキテクチャ制約・互換性
1. **Ring 0 カーネル純粋性とホスト単一調停境界**:
   - `packages/agent_kernel` は外部通信・FFI・HTML/YAML・UI 依存を持たない純粋 Dart パッケージのまま維持する。
   - 並列 `WorkspaceWorker` が稼働しても、`JjDriver` 更新ミューテックス、監査ログ追記（各子ワーカー専用 `jjChangeId` 帰属含む）、クオータ加減算（失敗リトライ消費計上含む）、プロセスツリー状態、および ACP 承認ゲートはすべてホスト Isolate 単一調停で原子的に管理する。
2. **ACP による上位 UI 分離原則とローカル Web カンバン GUI のローカルセキュリティ**:
   - カンバン GUI アプリ（`acp_kanban_app.exe`）はエンジン内部パッケージ（`agent_kernel`, `agent_drivers`, `agent_runtime`）を直接参照せず、純粋に ACP `stdio` プロトコル越しに `agent_os_daemon.exe` を駆動する（`REQ-11`）。
   - `acp_kanban_app.exe` の HTTP/WebSocket サーバーは必ず `127.0.0.1`（IPv4 ループバック）に限定バインドして LAN/外部網からの到達を遮断し、悪意ある外部サイトからのローカルポート踏み台攻撃（CSRF / Cross-Site WebSocket Hijacking）を防ぐため `Origin` ヘッダ検証および同一オリジン HTML（`<meta name="csrf-token">`）経由で配布するセッショントークン検証を強制する（CSRF トークンは標準出力やログに出さない）。またオフライン単体完結と情報漏洩防止のため埋め込み HTML/CSS/JS での外部 CDN 参照を一切禁止する。
3. **Zed ACP v1 プロトコル互換性と `stdout` 純度**:
   - ACP v1 Extensibility 規約（標準スキーマ直下に独自キーを追加せず、固有メソッドは `_fm_agent_os/*`、固有メタデータは `_meta["fm_agent_os/..."]` に格納）を厳守し、子 `Isolate` や `stdio` MCP サブプロセスの出力がデーモン `stdout` に 1 バイトも混入しない構造を維持する。
4. **TTY 独占原則とケーパビリティ単調減少の維持**:
   - Stage 3 で `WorkspaceWorker` に専用ワークスペース内編集を許可しても、ユーザーへの ACP 承認要求（`WAITING_APPROVAL`）を出せるのはフォアグラウンドの親（Ring 2）1 人のみとする原則は絶対維持する。また `WorkspaceWorker` と `WebResearcher` の権限（Workspace ⊕ Net 隔離）は混在させない。
5. **秘密情報の絶対非露出と本番 SSRF 非緩和・テスト用バックドア禁止**:
   - `OPENROUTER_API_KEY`、`OLLAMA_API_KEY` に加え、ACP `mcpServers` / `--mcp-server` で渡される `env[].value` 等の資格情報の実値は、`SecretRedactor` によりコンテキスト・`syscalls.jsonl`・`llm_io.jsonl`・`.agent_os/swap/` 退避ファイル・CLI/Web カンバン出力・証跡文書のすべてで `<REDACTED>` マスクし一切露出させない。
   - 本番 `agent_os_daemon.exe` の SSRF 非緩和原則を維持し、テスト専用の危険なクラッシュ／バイパス CLI フラグも本番バイナリへ一切持ち込まない。
6. **AOT 単一バイナリ互換性**:
   - 新規パッケージを追加する場合も Build Hooks / `dart:mirrors` 非依存の pure-Dart パッケージに限定し、`dart compile exe` による全 3 バイナリ（`agent_os_daemon.exe`, `acp_cli_client.exe`, `acp_kanban_app.exe`）の単一 `.exe` 生成を維持する。
7. **合意にない性能 SLO・数値品質目標の新設禁止**:
   - 応答レイテンシ秒数目標、スループット数値、コードカバレッジ率目標などの非機能数値目標は利用者から要求されていないため、根拠のない品質数値を新設しない（ミューテックスによる `jj op log` 無分岐、クオータ上限遵守、タイムアウト強制回収、コンテキスト枠内への Swap 収束は機能要求として検証する）。
