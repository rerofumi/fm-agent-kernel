## 2. 適用制約・非機能・検証範囲の方針

1. **非機能の追加要求**: 利用者からスループット・レイテンシ SLO・テストカバレッジ率等の新規数値目標は求められていないため、**合意にない数値目標や品質水準は新設しない**。
2. **検証の強さと Evidence class**:
   - 本環境（Windows 11 + Dart SDK + Jujutsu `jj`）において、`REQ-01`〜`REQ-07` はすべて自動テスト・ビルド確認（`E1`）、実プロセス／ACP 実行観測（`E2`）、および静的構造・実装境界照合（`E3`）によって直接検証可能であり、`EX`（直接確認不能）を要する項目はない。
   - 承認待ち中のタイマー一時停止検証（`REQ-05`）では、数分間の実時間待機を行う必要はなく、短縮した `heartbeatTimeoutMs` / `maxWallTimeMs`（数百 ms）と Completer 制御の承認ハンドラを用いて決定論的かつ高速に検証する。
3. **既存アーキテクチャ制約の維持**:
   - `packages/agent_kernel` は外部パッケージ・`dart:ffi`・`stdout` 非依存を維持する。
   - `packages/agent_runtime/lib/src/prompts/agent_prompts.dart` および `process_runner.dart` は `dart:io`・`agent_drivers`・`http` 非依存を維持する。
   - `packages/agent_acp/lib/src/kanban/`（および `bin/acp_kanban_app.dart`）はエンジン 3 パッケージ（`agent_kernel`, `agent_drivers`, `agent_runtime`）を import せず、`kanban_ui_assets.dart` に `http://` / `https://` 文字列を含めない純粋 wire 構成を維持する。
   - `.agent_os/` 配下ファイルの `PROTECTED_INTERNAL_PATH` 保護、および子プロセスからの再帰 `sys_spawn` / `sys_wait` 禁止（深度 1 固定）を維持する。
4. **対象外**: [20_app_requirement.md](./20_app_requirement.md) §4.2 記載の項目（Ring 3 でのシェル・メタ文字・生 `git`/`jj`・ネットワーク・`/workspace` 外アクセスの承認解禁、Ring 3 への `vcsTx`/`mcpCall`/`procSpawn` 解禁、PID 横断や永続化の `allow_always`、設定ホットリロード）は対象外とする。

## 4. 通常設計判断に委ねる事項（`40_specification.md` 対象）

以下は要求の目的・範囲・合意済み受け入れ条件を変えない技術詳細として、後続の `fm-dev-architect` が `40_specification.md`（および必要に応じた `42_spec_*.md`）で具体化する：

1. **JSON / API スキーマ詳細**:
   - `.agent_os/exec_policy.json` における子プロセス承認オプトイン設定フィールドの具体的なキー名・型（ブール値または対象プロファイル指定構造）とバリデーション警告文言。
   - `sys_spawn`（および `SpawnSpec`）における承認権オプトイン／明示無効化引数の表現（専用ブール引数と `requestedRights` の組み合わせ規則、および `explorer` / `web_researcher` 拒否時の具体的な `SyscallError.reason`）。
   - `sys_request_approval` の具体的な入力パラメータ JSON Schema（`syscall`, `args`, `reason` 等）と返却ペイロード構造（`approved`, `decision`, `alreadyAllowed`, `grantId` 等）。
2. **ワンタイム承認チケットと `ApprovalGate` 内部構造**:
   - 正規化済み引数に基づくチケット照合キーの決定的シリアライズ方式、同一プロセスが同一引数のチケットを重複取得した場合の扱い、および FIFO 直列化キューと個別 `CancellationToken` 離脱のデータ構造。
3. **タイマー合成一時停止と `SyscallGate` サスペンド再確認の細部**:
   - `_ManagedChild` における `isSuspended` と `isWaitingApproval` の参照カウント／フラグ合成方式、および `SyscallGate` Stage 4 完了直後の Stage 0.5 相当サスペンド待機フック位置。
4. **ACP `_meta` ペイロードとキャンセル通知連携**:
   - `session/request_permission` の `_meta` キー構造（例: `_meta["fm_agent_os/approval"]`）、承認待ちキャンセル／終了時に `AcpCliRunner` と `KanbanAcpBridge` が保留状態を即座にクリアするための通知／クリーンアップ手順、および `kanban_ui_assets.dart` での保留承認タイトル・3 選択肢ボタンの UI レイアウト。
